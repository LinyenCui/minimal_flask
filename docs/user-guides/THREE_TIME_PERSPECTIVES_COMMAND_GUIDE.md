# 🎯 三時間態命令架構指南

## 🌊 核心概念：今天是流動的邊界

> ⚠️ **這是理解系統最重要的概念，請務必理解！**

在這個派班系統中，**「今天」不是一個固定的時間態，而是一個流動的邊界**：

- **這一秒是「現在」，下一秒就變成「過去」**
- 班次在執行時間到達後，會自動從 `trips` 表（現在態）掉入 `completed_trips` 表（過去態）
- 因此，**今天這個日期同時存在著「現在態」和「過去態」的資料**

### 📊 今天的時間態判斷規則

| 查詢類型 | 關鍵字 | 查詢的表 | 說明 |
|---------|--------|----------|------|
| `今天司機61553班次` | 無「已完成」 | `trips` | 查詢今天還在生產線上的班次 |
| `今天司機61553已完成班次` | 有「已完成」 | `completed_trips` | 查詢今天已經完成的班次 |

### 📅 日期範圍查詢的時間態分隔

當查詢跨越多個日期時，系統會根據日期自動分隔：

```
查詢：12/1-12/25 司機61553 診所班次

系統處理：
┌─────────────┬──────────────┬───────────────┐
│   12/1-12/17  │    12/18     │   12/19-12/25  │
│   (過去態)    │   (今天)     │    (未來態)    │
├─────────────┼──────────────┼───────────────┤
│ completed_  │    trips     │     trips      │
│   trips     │  (無已完成)   │               │
└─────────────┴──────────────┴───────────────┘
```

但如果加上「已完成」關鍵字：

```
查詢：12/1-12/25 司機61553 診所已完成班次

系統處理：
┌─────────────┬──────────────┬───────────────┐
│   12/1-12/17  │    12/18     │   12/19-12/25  │
│   (過去態)    │   (今天)     │    (未來態)    │
├─────────────┼──────────────┼───────────────┤
│ completed_  │ completed_   │    不適用      │
│   trips     │   trips      │  (未來無已完成) │
└─────────────┴──────────────┴───────────────┘
```

### 🔑 實用範例

```bash
# 查今天還沒完成的班次（生產線上）
/今天司機61553班次
/今天診所班次

# 查今天已經完成的班次（已掉入完成倉庫）
/今天司機61553已完成班次
/今天診所已完成班次

# 跨日期範圍查詢
/12/1-12/25 司機61553 診所班次      # 混合查詢（過去+今天現在態+未來）
/12/1-12/25 司機61553 診所已完成班次 # 只查已完成的（過去+今天已完成）
```

## ❌ 當前問題
1. **命令混亂**：用戶容易混淆「班次詳情」和「查看」命令
2. **ID不統一**：trips表用trip_id，completed_trips表用id，容易出錯
3. **時間態錯配**：過去態班次用「班次詳情」查不到，但用戶不知道要改用「查看」

## ✅ 標準三時間態命令映射

### 🏗️ 未來態（整備區域）- fixed_schedules表
**目的**：管理班次模板和預約設定
```bash
# 模板管理
匯入固定班次 [週次]        # 從模板匯入到生產線
查詢固定班次 [客戶]        # 查看模板內容
固定班次請假 [ID] [加成] [原因]  # 長期請假設定
固定班次恢復 [ID]          # 恢復模板狀態

# 預約管理  
預約叫車                   # 新建未來班次
/固定班表 [客戶簡稱]        # 查詢客戶班表
```

### ⚡ 現在態（生產線區域）- trips表  
**目的**：管理正在執行的班次（包含今天和未來日期）
```bash
# 班次查詢（針對trip_id）
班次詳情 [trip_id]         # 查看生產線上班次詳情
東洋班次 [日期]            # 查看東洋/臨時班次
診所班次 [日期]            # 查看診所班次
查詢班次 [複雜條件]        # 複雜條件查詢

# 班次管理
指派司機 [trip_id] [司機ID]  # 分配工作人員
修改狀態 [trip_id] [狀態]    # 改變班次狀態
乘客請假 [trip_id] [加成] [原因]  # 臨時請假（障眼法）

# 範例
明天司機5386所有班次        # → 查詢班次 明天 司機5386
找狀態為待派的班次          # → 查詢班次 狀態=待派
```

### 📦 過去態（成品倉庫）- completed_trips表
**目的**：管理已完成班次的記錄和統計（針對completed_trip_id）
```bash
# 班次查詢（針對completed_trip_id）
查看 [completed_trip_id]    # 查看已完成班次詳情
查已完成 [複雜條件]         # 複雜條件查詢已完成班次
統計金額 [條件]            # 金額統計

# 車資管理
記錄車資 [completed_trip_id] [錶價] [加成] [原因]  # 記錄/修改車資
修改類別 [completed_trip_id] [新類別]             # 修改班次類別

# 報表生成
生成周報表 [類別]          # 生成週報
生成月報表 [類別]          # 生成月報

# 範例  
昨天司機533診所班次        # → 查已完成 昨天 司機533 診所
司機5386本月車資總和       # → 統計金額 本月 司機5386
```

## 🔄 ID轉換機制問題

### 當前狀況
- **trips表**：主鍵是`trip_id`（如1585, 1996等）
- **completed_trips表**：主鍵是`id`（自動生成，如1, 2, 3等）
- **問題**：班次完成後從trips轉移到completed_trips時，ID會變化

### 解決方案選項

#### 選項1：保持現狀 + 用戶教育
- 優點：無需改動程式碼
- 缺點：用戶需要記住兩套ID系統

#### 選項2：統一查詢命令
創建智能「班次查詢」命令，自動搜尋兩個表：
```bash
班次查詢 1585              # 自動在trips和completed_trips中搜尋
```

#### 選項3：保留trip_id到completed_trips
在completed_trips表中添加original_trip_id欄位，保存原始trip_id

## 🤖 智能路由建議

### 錯誤提示機制
當用戶輸入錯誤時間態命令時，提供智能引導：

```bash
用戶：班次詳情 123
系統檢查：trips表找不到trip_id=123
智能提示：
❌ 在生產線上找不到班次 #123
💡 可能的原因：
1. 班次已完成並移至成品倉庫
2. 班次ID輸入錯誤

🔍 建議操作：
• 查已完成 昨天 → 查看最近完成的班次
• 查看 [ID] → 查看特定已完成班次
• 東洋班次 今天 → 查看今天進行中班次
```
