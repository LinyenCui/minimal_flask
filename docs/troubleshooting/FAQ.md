# 🔧 常見問題解答 (FAQ)

## 🚨 緊急問題

### Q: 系統無法啟動，顯示模組錯誤？
**A:** 檢查以下項目：
1. 確認虛擬環境已啟動：`source venv/bin/activate`
2. 安裝依賴套件：`pip install -r requirements.txt`
3. 檢查環境變數：確認 `.env` 檔案設定正確
4. 檢查資料庫連線：確認 PostgreSQL 服務運行

### Q: Line Bot 無法回應訊息？
**A:** 檢查項目：
1. **Webhook URL**: 確認 Line 後台設定正確的 webhook URL
2. **憑證配置**: 檢查 `LINE_CHANNEL_SECRET` 和 `LINE_CHANNEL_TOKEN`
3. **網路連線**: 確認服務器可以連接到網際網路
4. **日誌檢查**: 查看 `logs/` 目錄下的錯誤日誌

```bash
# 檢查憑證
python -c "
import os
from dotenv import load_dotenv
load_dotenv()
print('Secret:', os.getenv('LINE_CHANNEL_SECRET')[:6] + '...')
print('Token:', os.getenv('LINE_CHANNEL_TOKEN')[:6] + '...')
"
```

### Q: 資料庫同步失敗？
**A:** 使用 [資料庫同步指南](../INCREMENTAL_SYNC_GUIDE.md)：
1. 檢查資料庫連線設定
2. 使用 `python test_incremental_sync.py` 測試
3. 在 Line 群組中輸入 `同步狀態` 查看狀態
4. 如果持續失敗，使用 `保護同步` 模式

## 📱 Line Bot 使用問題

### Q: 如何正確格式化預約命令？
**A:** 支援多種格式：
```
預約 2025/7/28 09:00 台北車站 到 松山機場
明天下午2點 從公司到客戶那邊
下周一早上8點半 去機場
```
系統支援自然語言，不需要嚴格格式。

### Q: AI 無法理解我的預約需求？
**A:** 嘗試以下方法：
1. 提供更明確的時間：`明天上午9點` 而非 `明天早上`
2. 包含完整地點：`台北車站東三門` 而非 `車站`
3. 使用關鍵字：在訊息中包含 `預約`、`安排`、`需要車`
4. 重新表達：用不同方式描述同一需求

### Q: 如何修改或取消已建立的預約？
**A:** 
```
修改預約 T20250728001    # 使用預約編號
取消預約 T20250728001    # 取消特定預約
查看我的預約             # 查看個人預約清單
```

## 🤖 AI 功能問題

### Q: AI 預約功能不準確？
**A:** 提升準確度的方法：
1. **提供上下文**: 說明出行目的和偏好
2. **確認細節**: AI 會詢問不確定的資訊，請配合確認
3. **使用完整句子**: 避免過度簡化的表達
4. **回饋改進**: 告知系統錯誤理解的部分

### Q: 如何使用圖片識別功能？
**A:** 
1. 直接傳送包含文字的圖片（會議通知、郵件截圖等）
2. 圖片中應包含時間、地點等關鍵資訊
3. 如 AI 無法識別，可以在圖片後補充文字說明
4. 支援中文和日文圖片內容識別

### Q: 多語言功能如何使用？
**A:** 
- **中文**: 系統預設語言，支援繁體中文
- **日文**: 直接使用日文輸入，系統自動識別
- **混合使用**: 可以在同一訊息中混用中日文

```
明日の朝8時に空港まで
明天早上8點到機場
```

## 📊 報表功能問題

### Q: 無法生成報表？
**A:** 檢查項目：
1. **權限**: 確認帳號有報表生成權限
2. **資料範圍**: 確認查詢期間內有資料
3. **Google Drive**: 檢查 Google Drive 服務狀態
4. **格式問題**: 確認日期格式正確

```
今日報表              # 基本日報
本週報表 詳細          # 詳細週報  
司機績效 張師傅 本月    # 特定司機績效
```

### Q: 報表內容不完整？
**A:** 可能原因：
1. **資料同步延遲**: 等待幾分鐘後重新生成
2. **權限限制**: 某些資料可能因權限而不顯示
3. **時區問題**: 確認報表時間範圍設定正確
4. **資料篩選**: 檢查是否有篩選條件影響結果

## 🔧 系統管理問題

### Q: 如何重置系統狀態？
**A:** 管理員操作：
```
系統狀態              # 查看當前狀態
資料庫同步            # 重新同步資料
系統重啟              # 重啟服務（謹慎使用）
```

### Q: 用戶權限設定問題？
**A:** 管理員功能：
```
用戶列表              # 查看所有用戶
用戶權限 [用戶ID] [權限等級]  # 設定權限
新增用戶 [用戶資訊]     # 新增用戶
```

### Q: 如何備份重要資料？
**A:** 
1. **自動備份**: 系統每日自動備份到 Google Drive
2. **手動備份**: 在群組中輸入 `資料備份`
3. **本地備份**: 管理員可通過指令匯出資料
4. **恢復資料**: 聯繫技術支援協助恢復

## 🌐 網路連線問題

### Q: 系統響應緢慢？
**A:** 檢查項目：
1. **網路狀況**: 確認網際網路連線穩定
2. **服務器負載**: 查看 `系統狀態` 了解負載情況
3. **同時用戶**: 高峰時段可能響應較慢
4. **功能複雜度**: 複雜查詢需要更多處理時間

### Q: 無法連接到 Render 資料庫？
**A:** 
1. 檢查 Render 服務狀態
2. 確認資料庫憑證正確
3. 檢查防火牆設定
4. 使用 `增量同步` 而非完整同步

## 🔍 調試和日誌

### Q: 如何查看系統日誌？
**A:** 
```bash
# 查看應用日誌
tail -f logs/app.log

# 查看同步日誌  
tail -f logs/sync.log

# 查看錯誤日誌
tail -f logs/error.log
```

### Q: 如何回報錯誤？
**A:** 在 Line 群組中：
```
回報問題 [詳細描述]
錯誤回報 [錯誤訊息]
建議功能 [建議內容]
```

提供資訊：
- 操作步驟
- 錯誤訊息截圖
- 發生時間
- 使用的功能

## 💡 效能優化

### Q: 如何提升系統效能？
**A:** 
1. **定期清理**: 清理過期日誌和暫存檔案
2. **資料庫維護**: 定期重建索引和統計
3. **監控資源**: 關注記憶體和 CPU 使用率
4. **批量操作**: 避免頻繁的小量操作

### Q: 記憶體使用過高？
**A:** 參考 [記憶體監控指南](./MEMORY_MONITORING.md)：
1. 重啟應用釋放記憶體
2. 檢查是否有記憶體洩漏
3. 調整工作進程數量
4. 清理無用的快取資料
