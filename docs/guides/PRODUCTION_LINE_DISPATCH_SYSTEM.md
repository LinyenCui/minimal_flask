# 🏭 生產線派班系統操作指南

## 📖 核心概念

### 將班次管理理解為一條日夜不停的生產線

想像我們的派班系統就像一條現代化的工廠生產線：

- **產品 = 班次記錄**：每個班次都是生產線上的一個產品
- **生產線 = 當前運行中的班次**：所有匯入的班次都在這條線上"流動執行"
- **自動化機制**：當執行時間到達時，班次會自動從生產線"掉入"已完成區域
- **工作人員(用戶)**：可以在產品完成前進行品質控制和干預

---

## 🎯 三時間態架構

### 🏗️ 未來態：整備區域
**資料表**：`fixed_schedules`、`customers` 等  
**本質**：工廠的原料倉庫和生產模板區  
**功能**：
- 客戶資料管理
- 固定班次模板設定
- 基礎配置準備

**操作關鍵字**：匯入、安排、固定班次、模板、準備

**典型操作**：
```
匯入固定班次 本週
設定客戶資料
管理班次模板
```

### ⚡ 現在態：生產線區域
**資料表**：`trips`（生產線主體）  
**本質**：產品正在生產線上"流動執行"  
**狀態流程**：
```
待派 → 準備 → (執行時間到達) → 自動掉入過去態
```

**工作人員干預機制**：
- **🏷️ 請假**：標記瑕疵但讓產品繼續跑完流程
  - 狀態依然是「準備」
  - 用 `passenger_leave_reason` 欄位記錄原因
  - 這是「障眼法」機制：骨子裡還是準備狀態
  
- **🚫 取消/衝突**：直接從生產線拿掉，防止掉入已完成
  - 徹底改變狀態為「取消」或「衝突」
  - 不會自動轉入完成階段

- **⏰ 30分鐘前修改**：最後調整機會
  - 防止運行中的班次被意外修改

**操作關鍵字**：今天、明天、當前、狀態、待派、準備、正在進行

**重要理解**：
> "明天司機5386所有班次" = 查詢明天已經匯入到生產線上的該司機班次
> 
> 無論是今天、明天或後天，只要是已匯入的班次，都屬於「現在態」

### 📦 過去態：成品倉庫
**資料表**：`completed_trips`  
**本質**：已完成的"產品"存放區  
**特點**：
- 記錄車資、收入數據
- 支援統計分析
- 績效評估依據

**操作關鍵字**：昨天、已完成、車資、收入、歷史、統計

**典型查詢**：
```
昨天司機533的車資
上週診所班次收入
查已完成 金額>200
```

## 🔧 實際操作範例

### 常見查詢模式

#### 1. 生產線監控查詢
```
# 查看今天生產線狀況
今天東洋班次
今天診所班次

# 檢查明天已安排的產品
明天司機5386所有班次
明天診所班次

# 生產線品質檢查
找狀態為待派的班次
查詢班次 狀態=準備
```

#### 2. 成品倉庫分析
```
# 收入統計
昨天司機533的車資
查已完成 今天 診所 金額>200

# 績效分析
上週東洋班次收入
司機5386本月統計
```

#### 3. 整備區域管理
```
# 模板管理
匯入固定班次 本週
固定班次請假 5 -50 診所乘客長期住院

# 客戶資料
查詢固定班表 王先生
```

### 工作人員干預操作

#### 請假處理（障眼法機制）
```
# 乘客臨時請假
乘客請假 139 -30 新建路乘客臨時有事

# 固定班次長期請假  
固定班次請假 5 -50 診所乘客長期住院
```

**處理邏輯**：
- 班次狀態保持「準備」
- 加成調整為用戶輸入值（通常負數或零）
- 顯示時會標示「請假（原因）」
- 班次依然會正常執行完整流程

#### 生產線移除操作
```
# 徹底取消班次
修改狀態 1826 取消

# 標記為衝突
修改狀態 1826 衝突
```

## 💡 系統設計哲學

### 自動化優先
- 生產線自動運行，減少人工干預
- 執行時間到達自動轉換狀態
- 預設流程涵蓋大部分場景

### 彈性干預
- 工作人員可在適當時機介入
- 請假機制保持業務連續性
- 緊急情況可移除問題產品

### 數據完整性
- 所有操作都有詳細記錄
- 修改原因和操作者追蹤
- 歷史數據完整保存

### 用戶友善
- 自然語言理解
- 智能路由到正確功能
- 錯誤處理和引導機制

## 🚀 AI智能理解

### 生產線思維查詢
AI系統能夠理解用戶的真實意圖：

```
用戶："明天司機5386所有班次"
AI理解：查詢生產線上明天已安排的該司機所有產品
系統路由：trips表查詢 + 司機篩選 + 日期篩選
生成命令：查詢班次 明天 司機5386
```

### 三時間態智能路由
- **金額查詢** → 自動路由到成品倉庫（completed_trips）
- **狀態查詢** → 自動路由到生產線（trips）
- **匯入操作** → 自動路由到整備區域（fixed_schedules）

### 容錯處理
- 無效狀態自動提示正確選項
- 格式錯誤提供範例引導
- 複雜查詢智能分解處理

## 📋 最佳實踐

### 日常操作建議
1. **早晨檢查**：查看今天生產線狀況
2. **司機安排**：確認待派班次的司機指派
3. **異常處理**：及時處理請假或衝突班次
4. **晚間結算**：檢查當日完成班次和收入

### 查詢效率提升
1. 使用自然語言描述需求
2. 善用司機編號和日期組合
3. 利用狀態篩選快速定位問題
4. 定期查看歷史數據分析趨勢

### 數據管理
1. 及時處理請假申請
2. 保持客戶資料更新
3. 定期檢查固定班次模板
4. 建立操作記錄檔案
