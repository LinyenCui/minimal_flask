# 固定班次乘客長期請假功能使用指南

## 📋 功能概述

此功能允許**乘客**在 `fixed_schedules` 層級設置長期請假，當匯入固定班次時，已請假的班次會自動帶入請假狀態到 `trips` 表中。這解決了乘客需要長期請假（如住院、出國等）時，避免每週都要重複設置請假的問題。

## 🛠️ 設置步驟

### 1. 資料庫結構升級

首先執行資料庫遷移，為 `fixed_schedules` 表新增必要欄位：

```bash
python add_fixed_schedules_status_migration.py
```

這會新增兩個欄位：
- `status` VARCHAR(20) DEFAULT '準備' - 班次狀態
- `note` TEXT - 說明備註

### 2. 透過 LINE bot 設置固定班次請假

#### 設置長期請假
在 LINE bot 中輸入：
```
固定班次請假 [固定班次ID] [加成] [請假原因]
```

範例：
- `固定班次請假 5 -50 乘客住院長期請假`
- `固定班次請假 12 0 出國一個月`
- `固定班次請假 23 -100 搬家不再需要此班次`

**參數說明：**
- **固定班次ID**：要設置請假的固定班次識別號
- **加成**：請假期間的車資調整金額（可為負數表示減免）
- **請假原因**：詳細的請假說明

#### 恢復班次狀態
在 LINE bot 中輸入：
```
固定班次恢復 [固定班次ID]
```

範例：
- `固定班次恢復 5`
- `固定班次恢復 12`

### 3. 查詢固定班次

#### 使用 LINE bot 查詢
在 LINE bot 中輸入：
```
/固定班表 [客戶簡稱]
```

範例：
- `/固定班表 新建路`
- `/固定班表 診所`
- `/固定班表 醫院`

**功能說明：**
- 根據客戶簡稱查詢相關的固定班次
- 顯示詳細的班次資訊（ID、時間、路線、車資、狀態等）
- 提供便利的操作按鈕：
  - 若班次為「準備」狀態 → 顯示「請假班次#ID」按鈕
  - 若班次為「請假」狀態 → 顯示「恢復班次#ID」按鈕
- 理論上每個客戶簡稱只會對應一個固定班次

#### 傳統查詢方式
你也可以使用現有的資料庫管理工具查看固定班次的狀態，或請系統管理員協助查詢固定班次 ID。

## 🔄 匯入行為

### 匯入邏輯

當使用「匯入固定班次」功能時：

1. **狀態為 '準備'** → 匯入到 `trips` 表時狀態為 '準備'
2. **狀態為 '請假'** → 匯入到 `trips` 表時狀態為 '請假'
3. **狀態為其他** → 匯入到 `trips` 表時狀態為 '準備'（預設）

### 匯入統計

匯入完成後會顯示詳細統計：

```
✅ 成功匯入 45 筆固定班次到本周 (3/10-3/16) (準備: 40筆, 請假: 5筆)。
```

## 📊 狀態說明

| 狀態 | 說明 | 匯入行為 |
|------|------|----------|
| 準備 | 正常班次 | 匯入為準備狀態 |
| 請假 | 長期請假班次 | 匯入為請假狀態 |

## 💡 使用場景

### 乘客長期住院

當診所乘客需要住院治療時：

1. 查詢乘客的固定班次 ID
2. 使用 `固定班次請假` 設置請假狀態
3. 匯入班次時自動標記為請假
4. 出院後使用 `固定班次恢復` 恢復

### 乘客出國/搬家

當乘客需要長期離開時：

1. 設置相關固定班次為請假狀態
2. 在原因中註明「出國一個月」或「搬家」
3. 返回後恢復狀態

### 定期停診

當診所有定期停診安排時：

1. 設置相關班次為請假狀態
2. 說明原因（如：「醫師休假」）
3. 恢復營業後恢復狀態

## 🔍 查看和監控

### 匯入後檢查

匯入班次後，可以透過現有的查詢功能檢查：

- 使用 LINE bot 的「查詢班次」功能
- 檢查「請假」狀態的班次是否正確匯入
- 請假班次會顯示為 🔵 狀態

### 確認設置

在 LINE bot 中設置固定班次請假後，會即時回覆確認訊息，包含：
- 固定班次詳細資訊
- 請假原因
- 下次匯入的影響說明

## ⚠️ 注意事項

1. **確認班次 ID**：設置前請確認固定班次 ID 是否正確
2. **狀態一致性**：請假狀態設置後，下次匯入才會生效
3. **恢復操作**：乘客請假結束後記得恢復狀態，否則會持續匯入為請假
4. **原因記錄**：建議記錄詳細的請假原因，便於後續管理

## 🛠️ 故障排除

### 如果找不到固定班次 ID

1. 請聯繫系統管理員查詢
2. 確認該乘客是否有固定班次安排
3. 檢查班次是否已被刪除或修改

### 如果匯入後狀態不正確

1. 確認設置時間在匯入時間之前
2. 檢查匯入日誌中的狀態統計
3. 確認 `fixed_schedules` 表狀態正確

## 💬 指令參考

```
# 設置長期請假
固定班次請假 [ID] [加成] [原因]

# 恢復班次
固定班次恢復 [ID]

# 現有的單次請假（trips 表）
乘客請假 [班次ID] [加成] [原因]
```

## 📈 功能優勢

- **減少重複操作**：一次設置，自動應用到所有匯入
- **狀態追蹤**：清楚記錄請假原因和時間
- **靈活管理**：隨時恢復，支援臨時調整
- **統計友好**：匯入時提供詳細的狀態統計
