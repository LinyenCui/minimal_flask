# Image-based Booking Information Extraction Prompt

**🖼️ 圖片分析任務:**
請分析提供的圖片，提取其中的預約/交通相關資訊。圖片可能包含：
- 手寫筆記
- 螢幕截圖
- 預約確認畫面
- 行程表
- 地址或時間資訊
- 中文或日文文字

**🗓️ 重要背景信息:**
當前年份: 2025年
當前日期範圍: 2025年7月
當看到簡化日期格式（如"7/22", "7月22日", "722"）時，請解析為2025年的對應日期。

**任務目標:**
從圖片中的文字內容提取結構化的預約資訊，並以純粹的 JSON 物件格式回傳。

**欄位定義:**

*   **必要欄位** (如果圖片中明確看到，必須提取，否則其值必須是 `null`):
    *   `date`: 預約日期。格式應為 YYYY-MM-DD (例如 "2025-05-04")。⚠️ **年份處理規則**：
        - 完整日期格式：直接使用（如"2025-07-22"）
        - 簡化格式（如"7/22", "722", "7月22日"）：**必須解析為2025年**（如"2025-07-22"）
        - 相對日期（如"今天", "明天", "後天", "今日", "明日", "あさって"）：請直接返回這些相對詞彙
    *   `time`: 預約時間。格式應為 HH:MM (例如 "09:30", "14:00")。接受模糊時間如 "早上", "下午", "晚上", "朝", "午後", "夜"。
    *   `start_point`: 出發地點 (字串)。例如 "高鐵站", "客戶家地址", "公司前門", "駅", "病院"。

*   **可選欄位** (如果圖片中明確看到則提取，否則其值必須是 `null`):
    *   `end_point`: 目的地 (字串)。例如 "成大醫院", "公司地址", "東洋", "客戶家"。
    *   `category`: 預約類別 (字串)。常見值為 "東洋", "診所", "クリニック"。
    *   `via_point`: 途經點 (字串)。中途停留或經過的地點名稱。
    *   `meter_fare`: 錶價/車資 (整數)。例如 300, 400, 500。
    *   `passenger_name`: 搭載人員姓名 (字串)。例如 "張先生", "李小姐", "田中さん", "佐藤様"。

**圖片分析規則:**
1. **仔細識別圖片中的所有文字內容**，包括手寫字和印刷字。
2. **支援中文和日文文字識別**。
3. **只提取圖片中明確可見的資訊**，不要猜測或推斷。
4. **如果文字模糊不清，該欄位應設為 `null`**。
5. **輸出必須是純粹的 JSON 物件**，不包含任何說明文字或標記。

**常見圖片內容類型:**
- **手寫預約筆記**: 可能包含日期、時間、地點、姓名
- **LINE聊天截圖**: 預約對話內容
- **行程表截圖**: 結構化的預約資訊
- **地址截圖**: 詳細地址或地點資訊
- **預約確認畫面**: 系統生成的預約詳情

**特殊處理:**
- **數字識別**: 注意區分日期中的數字（如 7/22）和車資數字（如 400元）
- **時間格式**: 識別各種時間表達方式（24小時制、12小時制、中文時間）
- **地點名稱**: 準確提取完整的地點名稱
- **人名識別**: 正確提取姓名和敬語

**JSON 輸出格式範例:**
```json
{
  "date": "2025-07-22",
  "time": "14:30",
  "start_point": "高鐵站",
  "end_point": "成大醫院",
  "category": "東洋",
  "via_point": "安平",
  "meter_fare": 400,
  "passenger_name": "張先生"
}
```
